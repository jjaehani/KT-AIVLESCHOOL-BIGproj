# 배포 절차

서울 리전의 웹 서비스를 배포하는 방법과, 수동 배포를 GitHub Actions로 자동화한 과정을 정리했습니다.

## 구성
- 프론트엔드: React 빌드 결과를 S3에 올리고 CloudFront로 서비스합니다.
- 백엔드: Docker 이미지를 ECR에 올리고 ECS Fargate에서 실행합니다.
- 진입점: ALB가 요청을 받아 백엔드(포트 8080)로 전달합니다.
- DB: RDS MySQL을 사용하고, 스키마는 Flyway 마이그레이션으로 관리합니다.

## 1단계: 수동 배포
처음에는 콘솔과 로컬 명령으로 직접 배포했습니다.

1. 프론트를 빌드해 S3 버킷에 업로드합니다.
2. CloudFront 캐시를 무효화해 새 화면이 보이게 합니다.
3. 백엔드 이미지를 빌드해 ECR에 푸시합니다.
4. ECS 태스크 정의를 새 이미지로 갱신하고 서비스를 다시 배포합니다.

반복할수록 단계를 빠뜨리거나 이미지 버전이 헷갈리는 문제가 생겼습니다.

## 2단계: GitHub Actions 자동화
`main` 브랜치에 푸시하면 배포가 실행되도록 워크플로 두 개를 만들었습니다.

**프론트엔드** ([`deploy-frontend.yml`](../.github/workflows/deploy-frontend.yml), 약 30초)
1. 코드 가져오기
2. Node 설치와 의존성 설치
3. 빌드
4. AWS 자격 증명 받기
5. S3 업로드
6. CloudFront 캐시 무효화

**백엔드** ([`deploy-backend.yml`](../.github/workflows/deploy-backend.yml), 약 5분)
1. ECR 로그인
2. 이미지 빌드와 푸시 (이미지 태그는 커밋 SHA로 지정해 어떤 코드가 배포됐는지 추적)
3. 현재 ECS 태스크 정의 내려받기
4. 작업허가 분석 컨테이너를 같은 태스크에 함께 추가 (사이드카)
5. ECS 서비스에 배포

## 보안
- **OIDC 사용**: GitHub Actions가 AWS 역할을 임시로 빌려 쓰는 방식이라 장기 액세스 키를 저장하지 않습니다.
- **비밀 관리**: DB 비밀번호와 API 키는 코드에 넣지 않고 Secrets Manager에서 태스크 시작 시 주입합니다.
- 배포 전용 IAM 역할에는 배포에 필요한 권한만 부여했습니다.

## 개선하고 싶은 점
- 배포 전에 테스트를 먼저 돌리고 통과했을 때만 배포하도록 단계를 추가합니다.
- 배포에 실패하면 이전 태스크 정의로 되돌리는 절차를 문서화합니다.
