# 요구사항 인터뷰 기록

인프라를 만들기 전에 팀별로 인터뷰해서 필요한 것을 정리했고, 그 답을 바탕으로 구성을 정했습니다.

## 팀별 요구사항과 구성 방향

| 팀 | 확인한 내용 | 구성 방향 |
|---|---|---|
| 프론트엔드 | 빌드 산출물(정적 파일)만 배포, API는 REST이며 `8080/api/...` 경로 | 서버 없이 S3와 CloudFront로 배포, API는 로드밸런서에서 해당 경로로 라우팅 |
| 프론트엔드 | 웹 주소와 API 주소가 모두 필요 | Route53 도메인 준비를 요청 사항으로 기록 |
| 백엔드 | Spring Boot 단일 앱(Java, Spring Security, Flyway), 포트 8080 | 컨테이너 1개로 실행, 외부용 80/443과 별도로 내부 8080 통신 규칙 추가 |
| 백엔드 | DB는 MySQL 8.4, Flyway가 앱 시작 시 자동 마이그레이션 | RDS MySQL 8.4 준비, DB 보안 그룹 포트를 5432(PostgreSQL)에서 3306(MySQL)으로 수정 |
| 백엔드 | 팀 프로젝트 규모(약 8명) | 최소 사양으로 시작 |
| 백엔드 | 외부 API 키는 현재 없음, 추후 OpenAI 등 추가 가능 | Secrets Manager는 필요한 시점에 구성 |
| 앱 개발 | 별도 Amplify 백엔드 없이 기존 백엔드 서버에 직접 연결 | 앱도 같은 API 엔드포인트 사용 |
| 앱 개발 | 로그인은 구현 방식 미정(JWT 등 검토), 푸시 알림은 위험 감지 시 검토 중 | 추후 SNS나 FCM 연동 여지를 남김 |
| 데이터 모델링 (감지 모델) | 공통 모델 1개와 클래스별 감지 모델 다수, PyTorch, 실시간 처리 필수, 학습은 완료되어 추론만 수행, 모델 파일 약 500MB, GPU 사양은 테스트 후 확정 | 중간 사양 GPU 인스턴스(g4dn.xlarge 등)로 시작 |
| 데이터 모델링 (유사 사례 검색) | 한국어 문장 임베딩 모델, PyTorch, 추론 전용, 실시간 여부 미정 | GPU 없이 CPU 인스턴스로 충분 |

## 클라우드 팀 액션 아이템
1. DB 보안 그룹 포트를 PostgreSQL(5432)에서 MySQL(3306)로 수정
2. 백엔드 내부 포트(8080) 통신 규칙 추가
3. 웹용과 API용 도메인 준비
4. 실시간 추론용 GPU 인스턴스와 임베딩용 CPU 인스턴스를 분리해 비용 절감
5. 푸시 알림(SNS, FCM)과 Secrets Manager 확장 여지 남겨두기

## 실제 구성과 달라진 점
- **도메인**: 별도 도메인을 구입하지 않고 CloudFront 기본 주소로 서비스했습니다.
- **Secrets Manager**: 필요한 시점에 구성했고, DB 비밀번호와 API 키를 여기에 두었습니다.
- **푸시 알림**: 인터뷰 당시에는 검토 단계였습니다. 이후 앱 기능으로 Firebase 푸시가 들어갔습니다.
